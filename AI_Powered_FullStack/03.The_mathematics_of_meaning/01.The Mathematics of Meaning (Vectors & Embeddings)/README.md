# Vector Embeddings & Semantic Search

A beginner-friendly learning project based on **Vector Embeddings, One-Hot Encoding, and Cosine Similarity**.

This project explores how text can be represented as numbers and how those numerical representations can be compared to find similarity between different pieces of information.

## 📚 What I Learned

### 1. Vectors

A vector is a list of numbers.

```text
[5, 1]
```

The number of values in a vector represents its number of dimensions.

For example:

```text
[5, 1]              → 2 dimensions
[5, 1, 8]           → 3 dimensions
[0.2, -0.4, 0.8]    → 3 dimensions
```

### 2. Dimensions

A dimension is one numerical position in a vector.

For example:

```text
[5, 1]
 ↑  ↑
 │  └── Dimension 2
 └───── Dimension 1
```

The lesson uses a simple 2D example such as:

```text
[Size, Length]
```

This is only for understanding the mathematics.

In real embedding models, dimensions are learned and do not usually have simple labels such as `Size`, `Length`, or `Is Frontend`.

### 3. Embeddings

An embedding is a numerical representation of information, such as text.

Conceptually:

```text
Text
 ↓
Embedding Model
 ↓
Vector
```

For example:

```text
"I love programming"
        ↓
[0.12, -0.44, 0.81, ...]
```

Real embeddings can contain hundreds or thousands of dimensions.

### 4. One-Hot Encoding

One-hot encoding represents categories using `0` and `1`.

For example:

```text
[Frontend, Backend]

React   → [1, 0]
Node.js → [0, 1]
```

These examples are useful for understanding cosine similarity, but they are **not real embeddings**.

### 5. Cosine Similarity

Cosine similarity measures how closely two vectors point in the same direction.

For example:

```text
[1, 0] vs [1, 0]
```

have a cosine similarity of:

```text
1.0
```

because they point in the same direction.

While:

```text
[1, 0] vs [0, 1]
```

have a cosine similarity of:

```text
0.0
```

because they are perpendicular.

### 6. Semantic Search

Semantic search focuses on the **meaning** of text rather than only matching exact words.

For example:

```text
"How can I learn programming?"
```

and:

```text
"What are the steps to become a software developer?"
```

may use different words but have related meanings.

Embeddings allow these meanings to be represented as vectors and compared mathematically.

## 🔄 Basic Concept

The main idea learned in this project is:

```text
Text
  ↓
Embedding
  ↓
Vector
  ↓
Compare Vectors
  ↓
Cosine Similarity
  ↓
Similarity Score
  ↓
Semantic Search
```

## 🎯 Key Difference

### One-Hot Encoding

```text
React → [1, 0]
```

* Uses simple `0` and `1` values
* Represents categories
* Usually sparse
* Manually defined categories

### Real Embeddings

```text
React → [0.12, -0.44, 0.81, ...]
```

* Uses many numerical values
* Generated by an embedding model
* Dense representation
* Dimensions are learned and not manually labeled
* Designed to capture relationships and meaning

## 🧠 Important Notes

* A **vector** is a list of numbers.
* A **dimension** is one position in a vector.
* An **embedding** is a vector used to represent information such as text.
* Real embedding dimensions are not normally human-readable features.
* **One-hot encoding is not the same as an embedding.**
* **Cosine similarity** can be used to compare vectors.
* Higher cosine similarity generally means the vectors are more closely aligned.
* Semantic search uses meaning rather than only exact keyword matching.
